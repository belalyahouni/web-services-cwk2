# COMP3011 Coursework 2 — Search Engine Tool

[![Tests](https://github.com/belalyahouni/web-services-cwk2/actions/workflows/tests.yml/badge.svg)](https://github.com/belalyahouni/web-services-cwk2/actions/workflows/tests.yml)

A small search engine for [`https://quotes.toscrape.com/`](https://quotes.toscrape.com/).
It crawls the site, builds an inverted index over all word occurrences, and
exposes a command-line shell with `build`, `load`, `print`, and `find`
commands. Implemented in Python 3 against the COMP3011 lecture material
(L9 Web Crawling, L11 Parsing & Tokenisation, L12 Indexing, L13 Query
Processing).

## Project structure

```
code/
  src/
    crawler.py        # BFS crawler with 6-second politeness window (L9)
    indexer.py        # HTML parsing + tokenisation + inverted index (L11, L12)
    search.py         # print and find commands (L13 conjunctive processing)
    main.py           # interactive command-line shell
  tests/
    test_crawler.py
    test_indexer.py
    test_search.py
    test_main.py
    test_integration.py
  data/
    index.json        # generated by the build command
  requirements.txt
  README.md
```


## Usage

Launch the interactive shell (either invocation works, run from the
project root):

```bash
python src/main.py
# or, equivalently:
python -m src.main
```

The shell offers four commands:

### `build`
Crawls `https://quotes.toscrape.com/` and writes the inverted index to
`data/index.json`. The crawler waits at least 6 seconds between requests
to the same server, as mandated by the brief and described in L9.

```
> build
Crawling https://quotes.toscrape.com/ (politeness window: 6 seconds)
  fetching https://quotes.toscrape.com/
  fetching https://quotes.toscrape.com/login
  ...
Crawled 50 pages. Building inverted index...
Index built (2731 unique terms across 50 documents).
Saved to .../data/index.json
```

### `load`
Loads a previously built index from `data/index.json` without re-crawling.

```
> load
Loaded index (2731 unique terms across 50 documents).
```

### `print <word>`
Prints the inverted-list entry for a single word (case-insensitive).

```
> print nonsense
Inverted list for 'nonsense' (1 document(s)):
  https://quotes.toscrape.com/author/Lewis-Carroll/
    frequency = 1
    positions = [42]
```

### `find <term> [<term> ...]`
Returns all pages containing **every** query term (conjunctive
processing — L13), ranked by **TF-IDF score** (sublinear tf with
standard inverse document frequency, per Manning et al. *Introduction
to Information Retrieval* ch. 6). Highest-scoring page first; ties are
broken by URL for reproducible output. The search is case-insensitive.

```
> find indifference
1 matching page(s) (ranked by TF-IDF):
  [1.6990] https://quotes.toscrape.com/page/3/

> find good friends
1 matching page(s) (ranked by TF-IDF):
  [1.4771] https://quotes.toscrape.com/page/3/
```

### `phrase <term> [<term> ...]`
Returns pages containing the given words **as a consecutive phrase**,
using the per-token positions stored in the inverted index (L12 slide
15 "Positions"). Pages are ranked by phrase-occurrence count
descending (URL tie-breaker). Quoted and unquoted forms produce the
same result; `find` and `phrase` differ in that `find` matches any
co-occurrence whereas `phrase` requires adjacency.

```
> phrase "good friends"
1 page(s) containing the phrase:
  [1 occurrence] https://quotes.toscrape.com/page/3/
```

`quit` (or Ctrl-D) exits the shell.

## Testing

66 tests, 99% line coverage. The suite mocks the network so it runs
offline and instantly.

```bash
pytest                          # all tests
pytest tests/test_crawler.py    # one file
pytest -v                       # list each test name
```

Tests must be invoked through `pytest`, not by running the test files
directly with `python` — `conftest.py` is what places `src/` on the
import path, and only `pytest` loads it.

| File | What it covers |
| --- | --- |
| `test_crawler.py` | Politeness window, internal-link filtering, visited set, fragment normalisation, HTTP errors, network exceptions, non-HTML content types, non-http schemes, relative URLs |
| `test_indexer.py` | Tokenisation edge cases, HTML parsing, inverted-index correctness (frequencies and positions), case-insensitivity, JSON round-trip |
| `test_search.py` | Single + multi-word search, conjunctive intersection, case-insensitivity, missing terms, empty queries, posting-list output |
| `test_main.py` | Each `cmd_*` in isolation and the REPL dispatch loop, including help, quit, EOF, blank lines, malformed quoting, and unknown commands |
| `test_integration.py` | End-to-end crawl → index → save → load → search; performance guards on build, find, and tokeniser |

## Design decisions

| Decision | Rationale |
| --- | --- |
| **All words indexed** (no stopword removal, no stemming) | L11 explicitly cautions that removing stopwords breaks queries like *"to be or not to be"*. The brief also asks for a record of *all word occurrences*. |
| **Frequencies + positions per posting** | The brief asks for "frequency, position, etc". Positions also keep the door open for phrase queries (L12 slide 15). |
| **Single JSON file persistence** | L12 slide 25 motivates putting all inverted lists into one file rather than one-file-per-term. JSON is human-readable so the index can be inspected directly during development. |
| **Term-at-a-time conjunctive `find`** | L13 describes term-at-a-time evaluation and conjunctive processing as the appropriate strategy for multi-word queries on small inverted lists. Intersecting posting-list document sets is O(min) in the smallest list. |
| **TF-IDF ranking (lnc.ltc)** | Conjunctive intersection picks *which* documents match; TF-IDF picks *what order* to show them in. Sublinear tf (`1 + log10(freq)`) prevents one heavily-repeated term from dominating, and idf (`log10(N/df)`) damps common terms. Standard formulation per Manning et al., consistent with L12/L13's term-weighting discussion. URL is used as a deterministic tie-breaker. |
| **Positional phrase search** | Storing per-token positions at index time (L12 slide 15) lets us answer adjacency queries directly: token *i* of the phrase must sit at position *p+i* in the document for some *p* where token 0 sits. This is the textbook positional-merge approach (Manning et al. ch. 2.4). Each candidate document costs `O(F * (k-1))` where *F* is the frequency of the first token and *k* is the phrase length, because position sets give O(1) "is *p+i* present?" lookups. |
| **6-second politeness window** | Mandated by the brief; L9 slide 12 describes this as the standard mechanism for being a well-behaved crawler. |
