# COMP3011 Coursework 2 — Search Engine Tool

A small search engine for [`https://quotes.toscrape.com/`](https://quotes.toscrape.com/).
It crawls the site, builds an inverted index over all word occurrences, and
exposes a command-line shell with `build`, `load`, `print`, and `find`
commands. Implemented in Python 3 against the COMP3011 lecture material
(L9 Web Crawling, L11 Parsing & Tokenisation, L12 Indexing, L13 Query
Processing).

## Project structure

```
code/
  src/
    crawler.py        # BFS crawler with 6-second politeness window (L9)
    indexer.py        # HTML parsing + tokenisation + inverted index (L11, L12)
    search.py         # print and find commands (L13 conjunctive processing)
    main.py           # interactive command-line shell
  tests/
    test_crawler.py
    test_indexer.py
    test_search.py
  data/
    index.json        # generated by the build command
  requirements.txt
  README.md
```

```bash
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Usage

Launch the interactive shell (either invocation works, run from the
project root):

```bash
python src/main.py
# or, equivalently:
python -m src.main
```

The shell offers four commands:

### `build`
Crawls `https://quotes.toscrape.com/` and writes the inverted index to
`data/index.json`. The crawler waits at least 6 seconds between requests
to the same server, as mandated by the brief and described in L9.

```
> build
Crawling https://quotes.toscrape.com/ (politeness window: 6 seconds)
  fetching https://quotes.toscrape.com/
  fetching https://quotes.toscrape.com/login
  ...
Crawled 50 pages. Building inverted index...
Index built (2731 unique terms across 50 documents).
Saved to .../data/index.json
```

### `load`
Loads a previously built index from `data/index.json` without re-crawling.

```
> load
Loaded index (2731 unique terms across 50 documents).
```

### `print <word>`
Prints the inverted-list entry for a single word (case-insensitive).

```
> print nonsense
Inverted list for 'nonsense' (1 document(s)):
  https://quotes.toscrape.com/author/Lewis-Carroll/
    frequency = 1
    positions = [42]
```

### `find <term> [<term> ...]`
Returns all pages containing **every** query term (conjunctive
processing — L13). The search is case-insensitive.

```
> find indifference
1 matching page(s):
  https://quotes.toscrape.com/page/3/

> find good friends
1 matching page(s):
  https://quotes.toscrape.com/page/3/
```

`quit` (or Ctrl-D) exits the shell.

## Testing

The test suite mocks the network so it runs offline and instantly.

```bash
pytest
```

Each module has its own test file under `tests/`. `conftest.py` at the
project root puts `src/` on the Python path so tests import the modules
directly.

Coverage focuses on:
- **Crawler** — politeness window enforcement, internal-link filtering,
  visited-set discipline, fragment normalisation, and graceful handling
  of HTTP errors and network exceptions.
- **Indexer** — tokenisation edge cases (case folding, punctuation,
  numbers, whitespace, stopwords), HTML parsing (script/style stripping),
  inverted-index correctness (frequencies and positions), and JSON
  round-tripping.
- **Search** — single-term lookup, multi-term conjunctive intersection,
  case-insensitive querying, missing terms, empty queries, and queries
  that tokenise to nothing.

## Design decisions

| Decision | Rationale |
| --- | --- |
| **All words indexed** (no stopword removal, no stemming) | L11 explicitly cautions that removing stopwords breaks queries like *"to be or not to be"*. The brief also asks for a record of *all word occurrences*. |
| **Frequencies + positions per posting** | The brief asks for "frequency, position, etc". Positions also keep the door open for phrase queries (L12 slide 15). |
| **Single JSON file persistence** | L12 slide 25 motivates putting all inverted lists into one file rather than one-file-per-term. JSON is human-readable so the index can be inspected directly during development. |
| **Term-at-a-time conjunctive `find`** | L13 describes term-at-a-time evaluation and conjunctive processing as the appropriate strategy for multi-word queries on small inverted lists. Intersecting posting-list document sets is O(min) in the smallest list. |
| **6-second politeness window** | Mandated by the brief; L9 slide 12 describes this as the standard mechanism for being a well-behaved crawler. |
